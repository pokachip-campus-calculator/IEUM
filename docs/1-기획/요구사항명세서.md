# 요구사항 명세서

> 개발해야 할 모든 기능/비기능을 리스트업하고 우선순위를 정하는 "개발 계약서". 기준은 이음 MVP 개발 기준서(공유 아티팩트 정본)이고, 2026-11-12 develop 코드에 맞춰 두었다. 노션 요구사항 명세서와 같은 내용이다.

## 우선순위 기준
- **P1 (Must)**: 없으면 서비스 오픈 불가 (핵심 기능). 노션의 "높음"
- **P2 (Should)**: 있으면 좋음 (보조 기능). 노션의 "중간"
- **P3 (Could)**: 시간 남으면 함 (고도화). 노션의 "낮음"

## 2. 비기능 요구사항 (Non-Functional) - 시스템이 "어떻게" 동작해야 하는가
ID 규칙: `NFR-SEC-001` (업무구분 약어 + 번호). 약어는 SEC 보안, PRV 개인정보, CMP 호환성, PRF 성능, OPS 운영, MNT 유지보수, USB 사용성이다.

| ID | 업무구분 | 요구사항 명 | 상세 설명 |
|---|---|---|---|
| NFR-SEC-001 | 보안 | 인증 토큰 | JWT 액세스 토큰 1개를 쓰고 로그인한 지 1시간 뒤 만료된다. 만료되면 401 `UNAUTHORIZED`가 오고 클라이언트는 토큰을 지운 뒤 로그인 화면으로 보낸다. 리프레시 토큰은 두지 않는다. |
| NFR-SEC-002 | 보안 | 로그인 실패 제한 | 같은 아이디로 5회 연속 실패하면 5분간 로그인을 막는다(429). 없는 아이디도 같은 방식으로 세어 계정 존재 여부를 알리지 않는다. 실패 횟수는 서버 메모리에 두므로 서버 1대 기준이다. |
| NFR-SEC-003 | 보안 | 비밀번호 보호 | 비밀번호는 BCrypt 해시로 저장하고 원문을 저장하거나 로그·응답에 남기지 않는다. |
| NFR-SEC-004 | 보안 | 접근 제어 | 가입·로그인만 공개이고 `/teacher/**`는 이음쌤만 호출한다. 학습자는 본인 자원만, 이음쌤은 담당 학습자의 자원만 볼 수 있고 아니면 `FORBIDDEN`이다. 컨트롤러는 토큰의 사용자 id만 쓴다. |
