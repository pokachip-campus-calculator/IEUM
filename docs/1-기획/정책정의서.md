# 정책 정의서

> 서비스 운영의 규칙, 제한 사항, 에러 처리 기준 (개발 로직에 녹여야 할 비즈니스 룰). 기준은 이음 MVP 개발 기준서(공유 아티팩트 정본)이고 2026-11-12 develop 코드에 맞춰 두었다. 규칙의 근거 API 번호는 괄호로 적었다. 노션 정책 정의서와 같은 내용이다.

## 1. 서비스 정책

### 가입·회원
| 정책 | 내용 | 근거 |
|---|---|---|
| 가입 대상 | 학습자만 가입한다. 이음쌤은 가입으로 만들지 않고 role=TEACHER로 가입하면 403 `TEACHER_SIGNUP_CLOSED`로 거부한다. 이음쌤 계정은 기관 확인 뒤 운영자가 DB에 직접 등록한다 | API 01 |
| 만 14세 미만 | 가입일 기준 만 14세 미만이면 보호자 이름·관계·연락처가 필수이고 `PENDING_GUARDIAN`으로 저장한다. 보호자 확인 전에는 로그인할 수 없다(403 `GUARDIAN_PENDING`). 동의 요청 자동 발송은 이번 범위에서 빼고 운영자가 기관에서 확인한 뒤 계정을 켠다 | API 01·02 |
| 가입 입력 규칙 | 아이디 영문·숫자 4~20자(대소문자 구분 없이 중복 불가), 비밀번호 8자 이상, 이름 필수, 닉네임 1~20자(중복 허용), 전화번호 숫자 10~11자리, 이메일·학교는 선택. 약관·개인정보 동의가 모두 true여야 한다 | API 01 |
| 간편 로그인·계정 찾기 | 제공하지 않는다. 비밀번호가 필요하면 운영자가 직접 초기화한다 | 기준서 1장 |
| 탈퇴 | 학습자만 할 수 있고 "기록이 바로 지워지는 것을 알고 있어요" 확인(`acknowledged:true`)이 있어야 한다. 탈퇴하면 학습 기록·쪽지·신호를 즉시 연쇄 삭제하며 되돌릴 수 없다. 이음쌤은 403 | API 06 |
| 장기 미이용 | 마지막 이용 뒤 1년이 지난 계정은 운영 SQL을 매월 수동으로 실행해 지운다(자동 배치는 보관) | 기준서 2장 |

### 학습
| 정책 | 내용 | 근거 |
|---|---|---|
| 점수 없음 | 점수·순위·맞고 틀림을 만들거나 남기지 않는다. 사전·사후 답은 달라졌는지(`changed`)만 비교한다 | 기준서 M3 |
| 완료 기준 | 마친 시각(`completed_at`)이 있으면 완료한 기록으로 센다. 다시 하는 중이어도 완료한 적 있는 것으로 센다 | API 07·08·11·17·18 |
| 다시 하기 | 학습자×연습당 기록은 1행이다. 다시 하면 답과 '나에게 한 줄'만 비우고 진행 중으로 되돌리며 `completed_at`은 지우지 않는다 | API 10 |
| 마침 조건 | UNIT은 사전 문항 전부·학습 카드 전부 읽음·사후 문항 전부, SCENARIO는 선택 1개, EMOTION은 단서와 마음 합쳐 1개 이상. 부족하면 `RECORD_INCOMPLETE` | API 10 |
| 이음쌤 없이 학습 | 학습(07~11)은 담당 이음쌤과 관계없이 끝까지 할 수 있다. 쪽지(12)만 이음쌤이 필요하다 | 기준서 2장 |
| 공개 연습 | 공개(`published=1`)된 연습만 목록·상세에 나온다. 연습 콘텐츠는 SQL 시드로 등록한다 | API 08·09 |

### 쪽지·배정·이관
| 정책 | 내용 | 근거 |
|---|---|---|
| 쪽지 입력 | 주제 5개(친구 관계·온라인·학교생활·집과 일상·그 밖), 본문 1~500자, 공백만은 불가 | API 12·15 |
| 자동 배정 | 첫 쪽지를 보낼 때 담당 학습자가 가장 적은 활성 이음쌤에게 배정한다(동률이면 id가 작은 쪽). 활성 이음쌤이 없으면 `NO_TEACHER_AVAILABLE` | API 12 |
| 쪽지 접근 | 학습자는 본인 쪽지, 이음쌤은 담당 학습자의 쪽지만 볼 수 있다. 아니면 `FORBIDDEN` | API 14·15 |
| 이음쌤이 못 보는 것 | '나에게 한 줄'과 시나리오 선택 답은 이음쌤 API에 내리지 않는다 | API 17·18 |
| 이관 | 이음쌤이 자기 담당 학습자를 다른 이음쌤에게 신청하고 받는 이음쌤이 수락하면 학습자의 담당과 모든 쪽지의 담당이 바뀐다. 학습자당 기다리는 신청은 하나만 둘 수 있다. 거절 기능은 없고 학습자에게는 알림을 보내지 않는다 | API 25·26 |
| 답변 안내 | 답변 시간과 "비밀을 무조건 지키지 않는다"는 안내는 서버 로직 없이 화면 문구로만 둔다 | 기준서 2장 |

## 2. 신호(안전) 정책
| 정책 | 내용 | 근거 |
|---|---|---|
| 검사 시점 | 학습자가 메시지를 저장하는 같은 트랜잭션에서 검사한다. 저장이 실패하면 신호도 남지 않는다 | API 12·15 |
| 검사 방식 | 본문을 소문자로 바꾸고 한글·영문·숫자만 남긴 뒤 신호 사전(`active=1`, 낱말형)의 정규화 값이 들어 있는지 본다. 초성 표현은 꺼 둔 채 보관한다 | 기준서 M5 |
| 등급과 건수 | 일치하는 낱말이 여럿이면 CRITICAL을 우선하고 같은 등급이면 id가 작은 하나로 메시지당 신호 1건을 만든다 | API 12 |
| 오탐 | 낱말이 우연히 들어간 글도 잡힐 수 있다. 화면이 "사람이 확인하는 첫 단서"라고 말하므로 그대로 둔다 | 기준서 5장 |
| 학습자에게 숨김 | 신호가 있다는 것과 찾은 낱말을 학습자에게 알리지 않는다. 학습자가 부르는 쪽지 API는 `signal`을 응답에 넣지 않는다 | API 12~15 |
| 이음쌤에게 보임 | 담당 이음쌤에게만 신호 목록·알림이 간다. 목록은 OPEN 먼저, CRITICAL 먼저, 최신순이고 찾은 낱말은 사전 원문 표현(공백 포함)으로 보여 준다 | API 20 |
| 대응 기록 | 처리 여부와 메모(500자 이하)를 남긴다. 처음 처리한 시각은 다시 눌러도 유지하고 메모는 학습자에게 보이지 않는다 | API 21 |

## 3. 알림 정책
| 정책 | 내용 |
|---|---|
| 생성 | 쪽지 저장·배정·이관 처리와 같은 트랜잭션에서 만든다. 별도로 알림을 만드는 API는 없다 |
| 종류 | `NOTE_RECEIVED`, `SIGNAL_FLAGGED`(이음쌤에게만), `REPLY_ARRIVED`, `NOTE_READ`, `TEACHER_ASSIGNED`, `LEARNER_ASSIGNED`, `TRANSFER_REQUESTED`, `TRANSFER_ACCEPTED` |
| 문구 | 제목·본문은 서버가 정해 둔 고정 문구만 쓴다. 쪽지 본문·학습자가 쓴 글·찾은 낱말은 담지 않는다 |
| 전달 | 앱 안에서만 보여 준다. 문자·메일로 보내지 않는다 |
| 조회 | 본인 알림만 최신순 최대 50건 내려주고 안 읽은 개수(`unreadCount`)를 함께 준다. 이관 알림에는 신청 상태(`transferStatus`: PENDING·ACCEPTED·EXPIRED)를 붙여 수락 버튼 표시 여부를 정한다. 남의 알림을 읽음 처리하면 `NOT_FOUND` |

## 4. 데이터·보안 정책
| 정책 | 내용 |
|---|---|
| 인증 토큰 | JWT 액세스 토큰 1개, 로그인한 지 1시간 뒤 만료. 리프레시·로그아웃 API는 없고 클라이언트가 토큰을 지운다 |
| 로그인 실패 | 같은 아이디로 5회 연속 실패하면 5분간 로그인을 막는다(429 `TOO_MANY_ATTEMPTS`). 없는 아이디도 같은 방식으로 세어 계정 존재 여부를 알리지 않는다. 횟수는 서버 메모리에 두며 서버 1대 기준이다 |
| 비밀번호 | BCrypt 해시로 저장한다. 현재 비밀번호가 틀려도 401이 아니라 400 `VALIDATION_FAILED`로 내린다(401은 클라이언트가 로그아웃으로 처리하기 때문) |
| 권한 | 가입·로그인만 공개. `/teacher/**`는 이음쌤만, 학습자 전용 API(07~13)를 이음쌤이 부르면 `FORBIDDEN`. 서버는 토큰의 사용자 id만 사용한다 |
| 개인정보 | 학습 기록·쪽지·신호는 탈퇴 시 즉시 삭제한다. 보호자 정보는 만 14세 미만 가입에서만 받는다 |
| 비밀값 | 비밀번호·JWT 비밀키·DB 접속 정보는 환경변수(`.env`)에서 읽고 공개 저장소에 커밋하지 않는다 |
| 시간 | 모든 시간은 한국 시간 ISO-8601(`+09:00`)로 내린다 |

## 5. 에러 정책
오류 응답은 `{code, message, fieldErrors}` 형식이고 `message`는 화면에 그대로 보여 주는 문장이다. 서버 내부 오류의 원인(예외 문구)은 응답에 넣지 않고 로그에만 남긴다. 아래 "화면 처리"는 2026-11-12 프론트엔드 코드(develop) 기준이다. 공통 규칙은 API 공통 호출 함수가 오류를 받으면 서버 메시지(`fieldErrors`가 있으면 첫 번째 메시지)를 화면이 그대로 보여 주는 것이고, 아래 표는 그 위에 따로 하는 처리만 적었다.

| code | HTTP | 화면 처리 |
|---|---|---|
| `VALIDATION_FAILED` | 400 | 서버가 준 첫 번째 `fieldErrors` 메시지(없으면 `message`)를 해당 화면의 오류 문구 한 줄로 보여 준다. 입력칸마다 따로 붙이지는 않는다 |
| `RECORD_INCOMPLETE` | 400 | 연습 화면에 서버 메시지("필수 선택이 빠졌습니다.")를 오류 문구로 보여 주고 그 화면에 그대로 머문다 |
| `UNAUTHORIZED` | 401 | 화면을 여는 중(라우트 로더)에 오면 저장된 로그인 정보를 지우고 로그인 화면으로 보낸다. 저장·전송 같은 버튼 동작 중에 오면 따로 처리하지 않고 서버 메시지를 오류 문구로 보여 준다. "시간이 지나 다시 로그인해 주세요" 안내는 아직 없다 |
| `BAD_CREDENTIALS` | 401 | 로그인 화면에 서버 메시지를 보여 준다(토큰이 없으니 로그아웃 처리는 하지 않는다) |
| `TOO_MANY_ATTEMPTS` | 429 | 로그인 화면에 "로그인 시도가 너무 많아요. 5분 뒤에 다시 시도해 주세요."를 보여 준다(서버 문구가 아니라 프론트가 정한 문구) |
| `GUARDIAN_PENDING` | 403 | 로그인 화면에 서버 메시지("보호자 확인이 끝나면 시작할 수 있습니다.")를 보여 준다 |
| `TEACHER_SIGNUP_CLOSED` | 403 | 가입 화면에 서버 메시지(운영 문의 방법 포함)를 보여 주고 입력한 값은 그대로 둔다 |
| `FORBIDDEN` | 403 | 이음쌤 화면을 여는 중에 오면 학습자 홈으로 보낸다. 그 밖의 화면에서는 따로 처리하지 않고, 버튼 동작 중이면 서버 메시지를 오류 문구로 보여 준다 |
| `NOT_FOUND` | 404 | 따로 처리하지 않는다. 버튼 동작 중이면 서버 메시지("요청한 정보를 찾을 수 없습니다.")를 오류 문구로 보여 준다 |
| `LOGIN_ID_TAKEN` | 409 | 가입 화면에 서버 메시지("이미 사용 중인 아이디입니다.")를 오류 문구로 보여 준다 |
| `NO_TEACHER_AVAILABLE` | 409 | 쪽지 쓰기 화면에 서버 메시지("배정된 이음쌤이 없습니다.")를 오류 문구로 보여 준다 |
| `TRANSFER_ALREADY_PENDING` · `TRANSFER_NOT_PENDING` | 409 | 신청(`TRANSFER_ALREADY_PENDING`)은 이음쌤 홈의 이관 신청 칸에, 수락(`TRANSFER_NOT_PENDING`)은 알림 화면에 서버 메시지를 보여 준다. 수락이 409이면 그 알림의 수락 버튼을 없앤다(목록을 새로 불러오지는 않는다) |
| `INTERNAL_ERROR` | 500 | 버튼 동작 중이면 서버 메시지("서버에 문제가 생겼습니다. 잠시 뒤 다시 시도해 주세요.")를 오류 문구로 보여 주고 사용자가 다시 누른다(자동 재시도 없음). 화면을 여는 중이면 오류 화면이 따로 없어 라우터 기본 오류 화면이 뜬다 |

## 6. AI 비용 방어 정책
이음 MVP는 서비스 안에서 AI 모델을 호출하지 않는다(신호 검사는 사전 낱말 포함 검사다). 그래서 1인당 질문 횟수 제한 같은 AI 비용 방어 정책은 두지 않는다. 입력 글자 수는 쪽지·메시지 500자, 나에게 한 줄 500자, 신호 메모 500자로 제한한다.
