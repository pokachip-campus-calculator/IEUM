# 이음 (IEUM)

위기 상황에 놓인 청소년이 안전한 곳에서 상황을 연습하고, 쪽지로 믿을 수 있는 어른(이음쌤)에게 도움을 청하는 학습·쪽지 서비스입니다.

- 점수나 순위를 남기지 않고, 내 속도로 연습합니다.
- 쪽지에 위험 신호가 있으면 **이음쌤에게만** 알려 줍니다. 학습자 화면에는 보이지 않습니다.
- 1주일 동안 3명이 만든 부트캠프 팀 프로젝트입니다.

## 누가 쓰나

| 사용자 | 하는 일 |
|---|---|
| 학습자 | 연습(질문지, 시나리오, 감정 읽기)을 하고, 내 학습 기록을 돌아보고, 이음쌤에게 쪽지를 보낸다 |
| 이음쌤 | 담당 학습자의 쪽지를 읽고 답하고, 위험 신호를 확인해 대응한다 |

## 주요 기능 (API 24개)

| 구분 | 기능 |
|---|---|
| 계정 (6) | 가입, 로그인, 내 정보 조회·수정, 비밀번호 변경, 탈퇴 |
| 학습 (5) | 홈, 학습 영역 목록, 연습 열기, 연습 기록 저장, 내 학습 기록 |
| 쪽지 (4) | 쪽지 보내기(이음쌤 자동 배정, 위험 신호 검사), 쪽지함, 쪽지 상세, 이어서 쓰기·답장 |
| 이음쌤 (6) | 요약 숫자, 담당 학습자 목록·상세, 받은 쪽지, 신호 목록, 신호 대응 처리 |
| 알림 (3) | 알림 목록, 읽음 처리, 모두 읽음 |

화면은 20개이고, 데이터는 테이블 8개에 저장합니다.

## 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 프론트엔드 | React 18, TypeScript, Vite, React Router, three.js(3D 마을) |
| 백엔드 | Java 21, Spring Boot 4, Spring Security(JWT), JPA |

| 폴더 | 내용 | 담당 |
|---|---|---|
| `frontend/` | 화면(React) | 프론트엔드 |

| `db/` | 테이블 DDL과 시드 SQL(V1~V5), 운영 SQL | DB |
| `docs/` | 기획, 설계(API·DB·ERD), 컨벤션 문서 | 모두 |

## 실행 방법 (내 컴퓨터)

세 가지를 모두 켜야 화면이 동작합니다: 데이터베이스, 백엔드, 프론트엔드.

1. **DB**: MySQL을 설치하고 DB를 하나 만든 뒤 `db/` 폴더의 `V1` → `V5` SQL을 번호 순서대로 실행합니다. 자세한 방법은 [db/readme.md](db/readme.md)를 봅니다.
2. **백엔드**: `backend/.env.example`을 `backend/.env`로 복사해 DB 접속 정보와 `JWT_SECRET`(32자 이상)을 채운 뒤, `backend` 폴더에서 `./gradlew bootRun`을 실행합니다. 서버는 `localhost:8080`에서 켜집니다.
3. **프론트엔드**: `frontend/.env.example`을 `frontend/.env.local`로 복사하고, `frontend` 폴더에서 `npm install` 후 `npm run dev`를 실행합니다. 화면은 `localhost:5173`에서 열립니다.

테스트는 `backend` 폴더에서 `./gradlew test`로 실행합니다. `.env` 파일은 비밀번호가 들어가므로 Git에 올리지 않습니다.

## 배포 구조

사용자는 Vercel에 올린 화면에 접속하고, 화면은 Railway에 올린 백엔드 API를 부르고, 백엔드는 같은 Railway의 MySQL을 읽고 씁니다. 배포 주소는 발표 때 공유합니다.

## 협업 규칙

- 이슈를 먼저 만들고, `develop`에서 `feature/…` 브랜치를 만들어 작업한 뒤 `develop`으로 PR을 올립니다.
- 커밋 메시지는 `타입: 한글 설명 #이슈번호` 형식입니다.
- 자기 담당 폴더만 수정합니다. 자세한 규칙은 [규칙.md](규칙.md)를 봅니다.
- 저장소가 Public이라서 비밀번호, 키, 접속 주소는 코드와 문서에 올리지 않습니다.
- PR에는 AI 코드 리뷰(CodeRabbit)를 사용하고, 병합은 사람이 합니다.

## AI 활용

설계 문서, SQL, 코드 초안과 보안 점검에 AI(Claude)를 사용했고, AI가 만든 결과는 팀원이 읽고 확인한 뒤 반영했습니다.

## 한계와 확장 계획

- **이메일 인증을 구현하지 않았습니다.** 이메일은 선택 입력입니다. 정식 운영 시에는 인증번호를 DB에 해시로 저장하고, 전용 도메인을 인증한 메일 서비스를 연동합니다.
- **이음쌤 계정은 운영자가 `db/ops.sql`로 등록하는 것이 원칙입니다.** 가입 화면에서 이음쌤으로 가입하는 경로를 막는 작업을 진행 중입니다.
- 로그인 시도 횟수 제한이 없습니다. 정식 운영 시 시도 제한을 둡니다.
- 이음쌤 강의 자료 올리기와 담당 이관 신청은 화면만 있고 서버 기능은 없습니다.
- 연습 콘텐츠는 6건이고, 생활·자립 영역은 준비 중입니다.
